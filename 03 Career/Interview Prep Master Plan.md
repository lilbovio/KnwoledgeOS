### Template
```
SITUATION: [Context - where, when, who]
TASK: [What was your responsibility]
ACTION: [What YOU specifically did - be technical]
RESULT: [Measurable outcome - numbers, time saved, users impacted]
```

## 🏗️ PART 3: System Design Practice

### Week 4: URL Shortener (Basic)

| Aspect | Your Design |
|--------|-------------|
| **Requirements** | Shorten URL, redirect, custom aliases, analytics |
| **API** | POST /shorten, GET /:shortCode |
| **Database** | PostgreSQL (shortCode → longURL mapping) |
| **Caching** | Redis for hot URLs |
| **Hashing** | MD5/Base62 for short code generation |
| **Scale** | 100M URLs, 100M redirects/day |

**Practice**: Draw diagram, explain tradeoffs, 30 min

---

### Week 5: Chat System (Intermediate)

| Aspect | Your Design |
|--------|-------------|
| **Requirements** | 1-on-1 messaging, online status, message history |
| **Protocol** | WebSockets for real-time, HTTP for history |
| **Database** | PostgreSQL (messages), Redis (online status) |
| **Message Queue** | Redis Pub/Sub or Kafka for fan-out |
| **Scale** | 10M users, 1M concurrent connections |

**Practice**: Draw diagram, explain WebSocket vs polling, 30 min

---

### Week 6: News Feed (Advanced)

| Aspect | Your Design |
|--------|-------------|
| **Requirements** | Post content, follow users, personalized feed |
| **Fan-out** | Write-time (push) vs Read-time (pull) |
| **Cache** | Redis for feed, CDN for images |
| **Database** | PostgreSQL (posts, follows), Redis (feed cache) |
| **Scale** | 1B users, 100M daily active |

**Practice**: Draw diagram, explain fan-out tradeoffs, 30 min
